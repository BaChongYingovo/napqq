# napqq

**一个零依赖的 QQ 聊天陪伴智能体。** 用 Python 标准库手写 WebSocket 客户端与大模型调用，
不需要 `pip install`，不需要 Node、Docker、git。

它不只会回话——有三档氛围感知、长期记忆、表情识别、拟人打字节奏，
还会在你没说话的时候自己找话说。

```
QQ 账号
   ↑  扫码登录 / 注入 NTQQ / 实现 QQ 协议
NapCat（协议端）        ← 这一层本项目没有，必须自备
   ↕  WebSocket（OneBot v11）
napqq（对话层）          ← 本项目：人设 / 记忆 / 情绪 / 自省 / 分段
   ↕  HTTPS
大模型 API
```

## ⚠️ 先说清楚它是什么

| 说法 | 对不对 | 说明 |
|---|---|---|
| 它是 NapCat 插件 | ❌ 不是 | 不被 NapCat 加载，**不要**往 NapCat 插件目录里放 |
| 它是独立进程 | ✅ 是 | 单独的 Python 进程，不寄生在 NapCat 内部 |
| 它能独立运行 | ❌ **不能** | **必须先装好 NapCat 并登录成功**，否则它连不上任何东西 |

原因：**napqq 里没有任何 QQ 协议代码**。登录 QQ、加密、心跳、设备指纹全在 NapCat 里。
napqq 只懂 OneBot v11 这一层（JSON 消息 + `send_group_msg` 这类动作名）。

所以两步缺一不可：**① 装 NapCat 并扫码登录 → ② 再启动 napqq。**

## 能力

- **人设稳定**：自带猫娘人设（`personas/小喵.txt`），三档氛围感知——轻松 / 走心 / 暧昧，
  其中走心档优先级最高（先接住对方说的话，再耍傲娇）
- **长期记忆**：滚动摘要压缩，情感线优先保留，跨会话记得专属互动
- **表情**：认得出 QQ 系统表情，也能自己发出（写 `/流泪` → 真实表情段）
- **拟人节奏**：按字数计算打字延迟、一条拆多条发、每轮有分条上限
- **规则层自省**：发送前查自曝身份 / 助手腔 / 过短 / 重复四类硬伤，命中就重生成
- **主动开口**：静默一段时间后自己找话说；有静默门槛、每日上限、免打扰时段，
  还会把"人呢""在吗"这种没话找话打回重写
- **可控暴露面**：私聊白名单（只回指定的人）、群聊可完全静默、单实例保护
- **数据隔离**：配置、数据库、日志全在用户数据目录，项目目录里不含任何隐私

## 1. 五分钟跑通

> **本机已经装好了。** NapCat 在 `<NAPCAT_DIR>`，QQ 已升到 9.9.33，账号已登录。
> 你只需要：先确认 NapCat 在跑，再 `python run.py`。详见 [DEPLOYMENT.md](DEPLOYMENT.md)。
> 下面是全新机器的完整流程。

### 第一步：启动 QQ 协议端（NapCat）

本机没装 Docker，走 Windows 直装：

1. 从官方仓库下载并部署 NapCat：<https://github.com/NapNeko/NapCatQQ>
   - 需要本机已装官方 QQ（NTQQ）客户端，NapCat 是它的宿主插件。
   - 装 Docker Desktop 的话用容器版更省事，但**不是必须**。
2. 启动 NapCat，终端/日志里会出现**登录二维码**（或一个二维码图片路径）。
3. 用你自己的手机 QQ 扫码登录。登录票据会被 NapCat 持久化，之后重启免扫码。
4. 在 NapCat 的网络配置里开启 **OneBot v11 的 WebSocket 服务端**，监听 `3001`，并设一个 access token（可选但建议）。

> 全程不涉及 QQ 密码，本项目代码里也没有密码字段。

### 第二步：填配置

```powershell
cd <你放这个项目的目录>
copy config.example.json config.json
notepad config.json
```

必须改的两处：

| 字段 | 说明 |
|---|---|
| `llm.api_key` | 大模型 key。也可以不填文件，改用环境变量 `DEEPSEEK_API_KEY` |
| `behaviour.owner_qq` | **只有这个 QQ 号能发管理指令**。填 `0` = 管理指令整体关闭，任何人都不能 `/pause` `/reset`（防止别人劫持你的机器人）。**默认 0** |

如果 NapCat 里设了 token，同步填到 `onebot.access_token`。

### 第三步：自检，再启动

```powershell
python run.py --check     # 检查配置 + 大模型连通性 + OneBot 连通性
python run.py             # 正式运行，开始收发消息
```

`--check` 会明确告诉你哪一步不通，不要跳过它。

## 3. 管理指令（仅 owner_qq 生效）

在 QQ 里直接发这些消息即可：

| 指令 | 作用 |
|---|---|
| `/pause` | 暂停回复，但继续记录上下文。卡住、说错话时先按这个 |
| `/resume` | 恢复 |
| `/reset` | 清空**当前会话**的记忆（含长期记忆摘要） |
| `/persona <新设定>` | 现场改人设，立即生效并持久化 |
| `/persona` | 查看当前人设 |
| `/memory` | 查看当前会话的长期记忆摘要 |
| `/forget` | 只清长期记忆，保留近期对话 |

## 4. 行为规则（`config.json`）

| 字段 | 默认 | 说明 |
|---|---|---|
| `behaviour.group_reply_mode` | `mention` | `mention`=只在被 @ 时回复；`all`=群里每条都回（会被踢，慎用）；`off`=群里装死 |
| `behaviour.private_reply` | `true` | 私聊是否自动回 |
| `group_whitelist` / `group_blacklist` | 空 | 白名单非空时，只在这些群活跃 |
| `private_blacklist` | 空 | 这些人私聊不理会 |
| `debounce_seconds` | `1.2` | 对方连发几条时先憋一下，合并成一次请求，避免逐条回 |
| `min_reply_interval_seconds` | `0.8` | 同一会话两条回复之间的最小间隔，纯粹为了让节奏像人。不想要就设 `0` |
| `active_hours` | `"09:00-24:00"` | 作息时段，**时段外只记录不回复**。空字符串 = 7x24 在线。支持跨零点（`"22:00-06:00"`）。格式写错会**拒绝启动**而不是静默变全天 |
| `at_sender` | `true` | 群聊里**回复谁就 @ 谁**。只加在第一条消息上。私聊不加。见 4.6 |
| `self_check` | `true` | **规则层自省**（总开关）：发送前检查自曝身份 / 助手腔 / 过短 / 重复，命中就重生成一次。见 4.8 |
| `avoid_repeat` | `true` | 只关重复那一条规则（`self_check` 的子开关） |
| `repeat_similarity` | `0.8` | 与最近 5 句的相似度阈值，超过就判定为重复。调低会更敏感、更容易重生成（多花 token） |
| `contacts`（顶层） | 见 4.4 | 联系人身份备注，让机器人知道某个人是谁 |
| `persona.system_prompt` | 见文件 | 人设核心。写得越具体越像人 |
| `persona.typing_style` | 开 | 把长回复按句号/换行拆成多条发，模拟真人打字 |
| `typing_style.max_chars_per_message` | `40` | 每条消息多长就断开。**这是"像不像真人"最关键的一个**，短=短句连发 |
| `typing_style.long_reply_threshold` | `200` | 回复超过这个字数就切到"长回复模式"（背长文必开，否则会被切成几十条消息） |
| `typing_style.long_reply_max_chars_per_message` | `350` | 长回复模式下单条的字符上限 |
| `typing_style.max_messages_per_reply` | `5` | **一条回复最多切成几条消息**，防炸屏的硬性兜底 |
| `llm.history_limit` | `24` | 每次请求带多少条历史。调大更连贯，也更贵 |
| `llm.temperature` | `0.9` | 高一点更像人，低一点更稳 |

想换模型：改 `llm.base_url` + `llm.model` 即可，任何兼容 OpenAI `/chat/completions` 的服务都行（OpenAI、Moonshot、本地 Ollama、vLLM）。

## 4.1 长期记忆（默认开启）

滑动窗口只有最近 24 条，聊久了会失忆。长期记忆解决这个：消息数超过阈值后，把**滑出窗口的部分**压缩成一段摘要存进数据库，之后每次请求都带上它。

```json
"memory": {
  "enabled": true,
  "trigger_messages": 40,     // 会话消息数超过这个就压缩
  "min_chunk_messages": 8,    // 少于这么多条不值得压一次
  "keep_recent": 16,          // 压缩后保留在窗口里的最近条数
  "max_summary_chars": 1200,  // 摘要长度上限
  "summary_model": ""          // 压缩用哪个模型，留空=和聊天同一个
}
```

要点：

- 压缩在**回复之后后台跑**，不占回复延迟；同一会话同时只跑一个压缩任务。
- 摘要会**滚动合并**（旧摘要 + 新对话 → 新摘要），不是简单丢弃。
- 摘要只记事实和关系（谁是谁、约定了什么），不记语气——语气是人设的事。
- 摘要之前的老消息**不再重复进窗口**，省 token。
- 压缩失败不影响正常聊天，下一轮再试。
- 用 `/memory` 看它记住了什么，`/forget` 让它忘掉。

压缩用的提示词在 [agent/memory.py](agent/memory.py) 里的 `COMPRESS_SYSTEM`，想让它记什么/不记什么直接改那里。

## 4.2 图片多模态（默认关闭）

默认情况下模型收到的是 `[图片]` 占位符，看不到画面。要让它真看图：

```json
"vision": {
  "enabled": true,
  "model": "",                    // 看图用哪个模型，留空=llm.model（该模型必须支持视觉）
  "image_transport": "auto",      // auto / url / base64
  "max_images_per_message": 2,    // 一条消息最多带几张图
  "max_image_bytes": 4194304,     // 单张上限 4MB，超了跳过
  "image_timeout_seconds": 20,
  "detail": "auto"
}
```

要点：

- **前提是模型支持视觉**。`deepseek-chat` 不支持，别直接开——带图请求会报 400。换支持视觉的模型，或用 `vision.model` 单独指定一个视觉模型。
- `image_transport`：
  - `url` 直接把图片链接交给模型（云端模型需要能访问该链接，QQ 图床链接通常可以）；
  - `base64` 由本机下载/读取后转成 data URL（本地模型、或图床拉不到时用）；
  - `auto` 端点在本机就用 base64，否则用 url。
- 图片标识会通过 OneBot 的 `get_image` 换真实地址；
- **带图请求失败会自动降级为纯文本重试**，一轮对话不会因为图片挂掉；
- 只有**当前这条消息**的图片会真的发进去，历史里的图片仍然是 `[图片]` 文字占位（控成本）；
- 视觉关闭时，提示词会明确告诉模型"你看不到内容"，避免它假装看见了。

## 4.3 作息时段（夜间静默）

「7x24 小时秒回」是风控眼里最硬的机器特征之一——真人要睡觉。`active_hours` 解决这个：

```json
"behaviour": {
  "active_hours": "09:00-24:00"
}
```

规则：

- **时段外只记录、不回复**。消息照常写进数据库，所以第二天它"知道你半夜找过它"，上下文是连续的，只是当时装睡。
- 支持**跨零点**窗口：`"22:00-06:00"` 表示晚上 10 点到次日早上 6 点**可以回复**（想反过来用就把限制时段理解成"活跃时段"）。
- 想彻底不限：填空字符串 `""`，或干脆删掉这一行。
- 分隔符宽松：`-`、`~`、`～`、`—` 都认；`09:00-24:00` 和 `9:00-24:00` 都行。
- **格式写错会直接拒绝启动**并在 `--check` 里报错，不会悄悄变成 7x24——否则你会以为自己受保护，实际全天在线。
- 起止写成一样（如 `09:00-09:00`）按"不限制"处理，避免误写导致永久静默。
- 管理指令**不受作息限制**：`/pause`、`/reset` 半夜发也照样生效（那是你本人的明确指令）。

启动日志会明确告诉你当前状态：

```
11:19:13 INFO  qqagent  作息: 09:00-24:00
```

处于静默时段时会额外警告一行，并且状态栏显示 `静默中(09:00-24:00)`，同时统计 `静默 N` 条：

```
[!] 当前处于静默时段，只会记录消息不回复。想立刻测试请把 behaviour.active_hours 临时清空。
```

**注意**：`--dry-run` 也遵守作息。半夜想验证链路的话，先临时把 `active_hours` 清空。

## 4.4 联系人身份备注（`contacts`）

让机器人知道「这个人是谁」，而不是当成陌生人。私聊时按备注对待；群聊里出现这些人时会点名标注。

```json
"contacts": {
  "100000004": {
    "alias": "女朋友",
    "relation": "女朋友",
    "notes": "叫她小柚。她讨厌被敷衍，回消息别太短。"
  },
  "100000001": {
    "alias": "主人",
    "relation": "",
    "notes": "别对他太客气"
  }
}
```

| 字段 | 作用 |
|---|---|
| `alias` | 你对这个人的备注，会作为「你对他的备注」注入 |
| `relation` | 身份关系。与 `alias` 相同时不重复注入 |
| `notes` | **最有用的一个字段**：任何你希望机器人记住的关于这个人的事（称呼、忌讳、共同经历、最近在忙什么） |

规则：

- 键必须是**纯数字 QQ 号**；非数字键会被忽略并在 `--check` 里报错。
- 三个字段全空的人等同于没登记。
- 私聊时注入 `【对方身份】` 段落，明确告诉模型「这是你本来就认识的人，不是陌生人」。
- 群聊时不会注入整段身份，但会列出「群里 X 是你认识的：女朋友」。
- `notes` 写得越具体，效果越好。别写「对她好一点」这种废话，写「她下周三答辩，别问成绩」。

## 4.5 喵语模式（背长文）

人设里内置了一条规则：**对方让你背正经长文（古诗文、课文、歌词、绕口令）时，必须照做，并且用喵语念**——原文每句结尾加「喵」，但不许改字、不许跳句、不许只背开头就停。背完加一句傲娇收尾。

例（实测输出）：

> 哼，大半夜的使唤本喵……就、就这一次哦，不许笑喵。
> 先帝创业未半而中道崩殂喵，今天下三分喵，益州疲弊喵，此诚危急存亡之秋也喵。
> …（中间省略）…
> 今当远离喵，临表涕零喵，不知所言喵。
> 哼，背完了，别得寸进尺喵。

配套的三个参数必须一起设，否则要么背一半被截断、要么炸成几十条消息：

| 参数 | 值 | 作用 |
|---|---|---|
| `llm.max_tokens` | `1600` | 出师表喵语版约 900 字，300 tokens 会被截断 |
| `typing_style.long_reply_threshold` | `200` | 超过 200 字切成长段落模式 |
| `typing_style.max_messages_per_reply` | `5` | 最多 5 条，硬性兜底防炸屏 |

**调人设时不要真发 QQ 消息**，用这个工具直接试：

```powershell
python tools\try_persona.py "用喵语背一下出师表"
python tools\try_persona.py "在吗" --who 100000004
```

它会打印实际发给模型的完整提示词、模型的原始回复、以及这条回复会被切成几条 QQ 消息（含每条字数）。不碰 QQ，也不会把话说错到群里。

## 4.6 回复谁就 @ 谁（`at_sender`）

默认开启。群聊里回复某人时，**第一条消息前会加上一个真正的 @ 段**，对方会收到通知。

```
"behaviour": { "at_sender": false }    // 关掉
```

规则与取舍：

- **只群聊生效**。私聊 @ 没有意义，不加。
- **只 @ 触发这次回复的那个人**（`batch[-1]` 的发送者，也就是防抖窗口里最后说话的人）。
- **只在第一条加**。分段回复时后续几条不加 @——每条都加等于反复通知，是骚扰也是风控敏感行为。
- **不重复 @**。如果模型自己已经写了 `@某人`，就不再额外加一个。
- **模型写的 `@数字` 会被转成真 at 段**（最多 3 个）。这一步很关键：模型输出的是纯文本 `@123456`，直接发出去对方**收不到任何通知**——发送前会把它换成 at 段。

实测发出的段结构（群聊，回复被拆成 2 条）：

```
id=37622164    [at, text]  真 at -> ['1727117403']   ← 第一条：真 @
id=1496302284  [text]                                 ← 第二条：不重复 @
```

**注意**：`at_sender` 打开后，群里的暴露面会变大一点点——被 @ 的人会收到通知，也就更容易注意到这个号。这在真人身上是正常行为，但一个机器人频繁 @ 陌生人，仍然是风控模型眼里的可疑信号。

## 4.7 表情识别（默认开启）
QQ 表情在 OneBot 报文里只是 `[CQ:face,id=4]` 这样一个数字。不做映射，机器人只知道"对方发了个表情"，不知道是哪个——**等于没看懂**。现在会把 id 还原成名字：

| 对方发的 | 报文里是 | 改进前模型看到 | 改进后模型看到 |
|---|---|---|---|
| 🙂 QQ 微笑 | `id=14` | `[表情]` | `[表情:微笑]` |
| 🐷 QQ 猪头 | `id=xx` | `[表情]` | `[表情:猪头]` |
| 😭 文字 emoji | 文本本身 | `😭`（本来就懂） | 不变 |
| 表情包 | `mface` | `[表情]` | `[表情包]` |

实测效果（真实群聊记录，模型原样回复）：

```
对方: @100000002 [表情:猪头]
机器人: 哈？！你、你才是猪头呢！拿这个表情砸本喵，你胆儿挺肥啊！
```

**映射表来源（重要）**：`agent/qq_faces.json`（329 条）不是手写的，是从 NapCat 自带的腾讯侧表情表提取的，并用公认的 OneBot 表情映射交叉校验——

```powershell
python tools\gen_face_table.py
```

脚本会检查 `id=0→惊讶`、`id=14→微笑`、`id=5→流泪`… 共 16 条标准映射，**全中才写入**，否则拒绝生成（防止 id 语义被换掉而静默出错）。运行时会打印映射条数：

```
长期记忆 : 开 | 图片识别: 关 | 表情识别: 329 条
```

**查不到的 id 不会瞎猜**，保留为 `[表情#88888]`。猜错等于曲解别人的情绪，比不认识更糟。

**这解决不了的**：图片表情、动画表情本质是图片，要让机器人看懂画面必须开 `vision` 并换成支持视觉的模型（`deepseek-chat` 不支持）。这类表情现在能识别到"这是个动画表情"，但看不到内容。

## 4.8 自我反思（规则层，`self_check`）

发送前对回复做一次**规则检查**，命中就重生成一次。抓四类最容易毁人设的硬伤：

| 命中原因 | 例子 | 纠正指令 |
|---|---|---|
| 自曝身份 | 「我是一个AI助手」 | 你绝不能承认自己是 AI/机器人/助手/程序 |
| 助手腔 | 「请问需要什么帮助」 | 不要用客服口吻，用你平时的语气 |
| 过短 | 「哦」 | 太短了对方接不住，说完整一点 |
| 重复 | 与最近 5 句相似度 ≥ `repeat_similarity` | 换个完全不同的说法重说一遍 |

设计要点：

- **判定顺序：自曝身份优先于助手腔**。「我是一个AI」同时命中两张词表，身份泄露更严重，
  必须用更针对性的指令纠正，不能被泛化的"助手腔"吃掉。
- **只重生成一次**（成本上限）。每次重生成都是一次模型调用，不能无限重试。
- **不做"每轮多调一次模型自省"**——那会让每轮成本和延迟直接翻倍。
  规则能抓的四类硬伤已经覆盖了最常见的破人设情况。
- 开关：`self_check` 是总开关，`avoid_repeat` 只管重复那一条。
  两个都关掉就跟没有自省层一样。

```
12:0x INFO  qqagent.bot  自省命中「自曝身份」，重生成一次：我是一个AI
```

## 5. 它是怎么工作的

```
QQ 账号 ──扫码──> NapCat（宿主 NTQQ，暴露 ws://127.0.0.1:3001）
                        │  OneBot v11 事件流 / API 调用
                        ▼
                agent/onebot.py  ── 读循环（只读，丢队列）
                        │                    │
                        │              echo 响应直接结算 Future
                        ▼
                   事件队列 ──> 派发任务（独立，不阻塞读）
                        ▼
                 agent/bot.py  ── 过滤 → 去重 → 防抖合并 → 组装上下文
                        ▼
                 agent/llm.py  ── urllib 调大模型（线程池，不卡事件循环）
                        ▼
                 send_private_msg / send_group_msg
```

关键设计点（都是踩过的坑）：

1. **读循环绝不能 await 事件处理器**。处理器内部发消息后要等 API 响应，而响应只能由读循环读出来——直接 await 就是死锁，表现为每条回复卡 20 秒超时。所以读循环只负责读+投队列，处理走独立派发任务。这个 bug 在开发中被集成测试抓出来了。
2. **echo 关联**：每个 API 调用带唯一 echo，响应按 echo 结算对应的 Future，支持并发调用。
3. **消息段格式兼容**：NapCat 可能发 CQ 码字符串（`string`）或消息段数组（`array`），两种都能解析；发消息时统一用数组格式。
4. **回显防护**：`self_id` 自己发的消息直接丢弃；`message_id` 做滑动窗口去重，防止重连后重复触发。
5. **断线自愈**：指数退避重连（2s→60s），重连后自动重新获取登录信息，未完成的调用立即失败而不是干等。


## 7. 已知限制

- **图片要显式开启且模型得支持视觉**。默认关闭，`deepseek-chat` 不支持视觉，开了会报 400（会自动降级为纯文本，但等于白开）。
- **历史消息里的图片不会重发给模型**，只有当前这条消息的图片会。这是成本取舍。
- **不能主动说话**。只有收到消息才回复，没有定时/主动发起。要做的话在 `bot.py` 里加定时任务即可。
- **长期记忆是单层的**。只有一段滚动摘要，没有向量检索、没有实体图谱。会话特别长（几千轮）时摘要会丢早期细节。
- **单账号**。多账号要多个 NapCat 实例 + 独立 IP。
- **协议端非官方通道**，腾讯有能力识别并处置。用主号是自己承担风险，建议注册一个小号先跑一周。
- **未在真实 QQ 上验证**。离线链路（协议解析、WebSocket、语气编排、指令、重连、记忆压缩、图片编码）已全部被测试覆盖，但真实 NapCat 的行为差异只能联调时暴露。第一次跑请盯着日志。

## 8. 联调排查顺序

出问题按这个顺序查，别乱猜：

1. `python run.py --check`
   - 报"模型不可用" → key、base_url、余额、网络代理
   - 报"OneBot 连接失败" → NapCat 是否在跑、WS 服务端是否开启、端口/Token 是否一致
2. 连上了但不回复：看日志里有没有 `请求模型`。
   - 没有 → 消息被过滤了。检查群聊是否 @ 了机器人（`group_reply_mode=mention` 时只认 @）、是否命中黑名单、是否处于暂停状态。
   - 有 `请求模型` 但报错 → 模型侧问题，日志里有 HTTP 状态码和响应体。
3. 回复了但发不出去 → 看 `发送失败` 的日志，通常是 NapCat 侧掉线或风控限制。
4. 群里回得太勤/太像机器人 → 调大 `debounce_seconds`，把 `group_reply_mode` 收紧，或调低 `temperature`。
5. 开了视觉后模型报 400 / `does not support image input` → 模型不支持视觉，换模型或把 `vision.enabled` 关回去。
6. 感觉它失忆 → `/memory` 看摘要里有什么；摘要没写进去的内容就是它真不记得，可以调大 `max_summary_chars` 或改 `COMPRESS_SYSTEM` 的侧重。

## 全新 clone 后的两步准备

```bash
# 1. 生成 QQ 表情映射表（从你自己本机安装的 NapCat 读取，仓库里不含该数据）
python tools/gen_face_table.py

# 2. 准备配置（config.json 不在仓库里，因为它会存你的 API key）
cp config.example.json config.json   # Windows: copy config.example.json config.json
```

然后 `python run.py --check` 看三项连通性，`python tests/test_integration.py` 跑测试。

### 人设

仓库自带一套猫娘人设（`personas/小喵.txt`）。`config.example.json` 里
`persona.system_prompt` 留空、`name` 写「小喵」，启动时会自动从
`personas/小喵.txt` 加载正文——所以改人设直接改那个 txt 就行。

想看清单或切换：

```bash
python tools/use_persona.py --list
python tools/use_persona.py 小喵 --target <QQ号>
```

想自己写一套：在 `personas/` 放一个 `<名字>.txt`，在 `personas/personas.json` 里登记，
然后 `python tools/use_persona.py <名字>`。也可以把自己的版本放到用户数据目录里覆盖仓库自带的。
